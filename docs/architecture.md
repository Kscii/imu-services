# 服务架构与数据流

服务 1.1.1、推理库 1.0.1、HTTP v2、数据库 schema 2。标准输入为规范胸前佩戴的 25 Hz 六轴及掩码；模型计算细节见推理库模型手册。一个任务在创建时确定计算模式、模型及配置，已开始任务不热换模型。

## 单机部署拓扑

```mermaid
flowchart LR
    U["公司上游服务：设备解包、对时、标准化、保留原始记录"] -->|"写 token；标准 HTTP v2"| A["接入 API：校验／幂等／限额"]
    A --> P[("PostgreSQL：持久输入、任务、租约、检查点、结果")]
    P <--> I["分块 worker 池：SB1 / FC1 + 可选 GP2"]
    P <--> W["整段 worker 池：实验 E7 + 可选 GP2"]
    P --> Q["query：数据库只读角色；查询、小时／日／周分析"]
    B["公司业务／客户分析调用方"] -->|"读 token"| Q
    M["migrate：schema 与数据库角色初始化"] --> P
    P --> BK["备份脚本：dump + 校验；异地目的地由部署方配置"]
```

API 与 worker 复用 runtime 镜像，query 与初始化复用 query 镜像；两个镜像连同 PostgreSQL 构成完整部署。数据库不暴露宿主机端口，API/query 默认只绑定回环地址，受控跨机入口由客户配置 TLS。持久队列位于 PostgreSQL，不依赖单独 Redis 或消息队列基础设施。

## 接入、计算与查询

```mermaid
sequenceDiagram
    participant U as 上游
    participant A as API
    participant P as PostgreSQL
    participant W as 匹配模式的 worker
    participant Q as query
    U->>A: 创建任务，固定模式／配置／请求幂等键
    A->>P: 事务写入任务
    U->>A: 分块上传，或完整记录上传并封口
    A->>P: 校验位置、重复提交与容量，持久保存
    W->>P: 获取租约及 fencing token
    P-->>W: 可计算范围与检查点／完整输入
    W->>W: 固定版本推理
    W->>P: 同一事务提交结果、进度、检查点
    U->>Q: 查询任务、分页结果、统计
    Q->>P: 只读结果及覆盖范围
    P-->>Q: 已提交版本的结果
    Q-->>U: 时间线、分类时长、实验步数
    U->>A: incremental 的 seal，确认最终位置
    A->>P: 标记可处理尾段
    W->>P: 完成尾段并提交终态
```

上传包长不决定算法上下文。分块模式正常累计 90 秒后发布首个 60 秒核心，后续每 60 秒推进；完整模式使用整条记录，上游可在录制结束时提交，不强制等自然日末。时区和日历统计按接口约定处理，缺失时间不会补成静止或零步。

## 恢复、过载与升级

```mermaid
flowchart TD
    X["worker 异常退出"] --> L["租约超时／任务重新可领取"]
    L --> F["新 worker 领取新 fencing token"]
    F --> C{"任务模式"}
    C -->|incremental| S["恢复已提交检查点，继续未提交范围"]
    C -->|whole_record| R["从持久完整输入重新计算"]
    S --> T["事务提交；旧 worker token 不能覆盖新结果"]
    R --> T
    O["待处理字节／任务达到限额"] --> E["返回可重试错误；调用方退避重试"]
    V["准备升级"] --> D["暂停新任务接入，完成上传／seal 并排空"]
    D --> B["备份数据库与旧配置、保留旧镜像"]
    B --> U["校验新镜像来源／schema／任务指纹"]
    U --> H["启动、健康与接口验证后恢复接入"]
```

不同模式有独立计算池和容量上限；不会因 whole_record 占用计算而改用分块模型。终态清理服务保存的输入，重算依赖上游重传；不宣称底层 WAL 或备份已经物理擦除。`restart` 处理进程退出，持续 unhealthy 仍需部署方监控。

本补丁的模型参数和计算不变，但库版本和代码摘要会改变任务指纹，不能接着恢复旧库检查点。这里只交付单机可部署的软件及恢复机制，生产高可用、异地备份位置、报警接收方和客户负载容量需在接收环境落实。

# 交付清单与接收标准

交付版本：服务 1.1.1、推理库 1.0.1、HTTP v2、数据库 schema 2。

| 交付对象 | 入口与内容 |
|---|---|
| 推理库仓库 | https://github.com/Kscii/imu-inference ：模型、算法、Python API、完整模型手册、来源及指标证据 |
| 服务仓库 | https://github.com/Kscii/imu-services ：持久接入／计算、查询分析、接口、部署、运维、架构和测试 |
| 推理库 Release | v1.0.1：wheel、经验证的 sdist、源码快照、校验及构建验证 |
| 服务主 Release | v1.1.1：轻量在线部署包、完整离线包、校验、精确镜像摘要及验证材料 |
| GHCR | runtime/query 两个应用镜像，部署使用不可变摘要，更新不覆盖旧版本 |

无需第三个仓库；普通部署人员从服务 Release 开始，算法团队从推理库模型手册开始。旧标签与 Git 历史保留，旧 Release 保持草稿。参与者评估表使用 unikey。

## 接收操作

按 README 在线安装，验证健康、两种模式的标准输入上传、封口／完整提交、分页结果、活动统计及日历计步。完整离线包额外验证外层与内层 SHA256、镜像导入和空数据库安装。公开接收检查使用无维护者凭据的隔离环境；API 身份验证使用接收方新生成的本地 token。

本轮完成条件是源码、模型、镜像、文档及对应工程证据齐全，接收方可以独立部署与调用。以 Release 的实际发布核对记录和 acceptance.json 为准，候选代码、草稿、CI 单项通过都不自动等同于正式交付完成。

## 验证边界

- 原有分类与时长指标见推理库模型手册；补丁回归验证固定输出没有退步，不构成新增准确率试验。
- 公开合成样例证明部署和 API 流程，不能证明动作分类准确率。
- 原始信号、设备视频和完整研究重训工程不随包分发。独立复算研究准确率需要另行取得对应原始输入与标注。
- 客户生产主机、TLS、上游设备协议、异地备份、报警和实际负载验收由后续部署阶段完成；客户准确率需要冻结方案后的新人员／设备数据验收。
- 自有代码 MIT，署名 Kscii；具体模型授权以推理库 MODEL_LICENSES.md 为准。

软件交付、生产部署和客户准确率验收分别记录，不以“发布成功”替代另外两项。
